  -   - Measured FIRST (Claude, 2026-10-31, RTX 5060 Ti, OpenGL3 on NVIDIA via PRIME, vsync off, 1280x720, crowd game, 100 AutoPlay turns, Skip mode, scenario autoplay-refresh run on the host with a copied dotnet runtime like gpu-bench.sh): 317-348 ms per turn with the per-turn Refresh; 192 ms per turn with Refresh removed entirely, so the engine's own turn (10 AI civs) is 192 ms and the full redraw costs about 130-200 ms per turn (the synchronous part of Refresh alone, timed with Time.GetTicksUsec, was 94-105 ms/turn; the rest is the async RefreshHud/RefreshSelection and node frees). The T376 figure of 0.5-0.8 s came from software GL (llvmpipe); the same scenario under Xvfb/llvmpipe now runs 241 ms/turn.
        Fix: a run that skips animations redraws the whole screen (GameScreen.Refresh: map, overlays, minimap, units) only after every AutoPlayModel.SkipRefreshInterval (10th) turn, and once when the run ends (natural end, refusal, error or Stop) if the last turns were not drawn yet (autoPlayStale; a Stop redraws once, not twice). The HUD (turn, top bar, notifications) still follows every turn through SnapshotChanged. Fast and Normal still redraw after each turn (units must stand where the next animation starts). Result on the RTX 5060 Ti, same scenario: interval 1 (before) 422 ms/turn, interval 5 about 290, interval 10 222 ms/turn (floor with no redraw 215), i.e. the per-turn cost is back to the engine's own cost. What the player sees when the run stops is unchanged (final redraw; asserted: every engine unit has its node on its tile, no other node).
        Deliberate behaviour change: during a Skip run the map, overlays and minimap update every 10 turns (about 2 s) instead of every turn. Recorded as an intentional improvement; the interval is a constant, not an option.
        Harness: new scenario autoplay-refresh (in scenarios.txt, passes under Xvfb in about 30 s and on the real GPU) asserts a COUNT budget, not a time (no Stopwatch/clock assertion): 100 skip turns redraw exactly 10 times, a 7-turn skip run exactly once (the end-of-run redraw), a fast run 6 times for 6 turns, and the view matches the engine after each run; it prints AUTOPLAY-REFRESH ms/turn and the adapter name (report only; HarnessDeterminismTests AllowedClockUsers entry added). Unit test: AutoPlayModelTests.ASkipRunRedrawsTheScreenEveryTenthTurn.... GameScreen.FullRefreshCount is a new public counter for it. autoplay and autoplay-animations still pass.
        Not done: a true dirty-region Refresh (only changed tiles/overlays/minimap) was not built; with the redraw at one in ten turns it costs 7 ms per turn on average (222 vs 215), so there is nothing left worth a second code path. Gate green (8786 passed, 0 failed).
