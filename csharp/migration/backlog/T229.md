  - Implemented. Engine: Unciv.Core/Console/* (namespace Unciv.DevConsole; not Unciv.Console, which shadows System.Console inside Unciv.*): CliInput (parser, Dashed/Quoted, autocomplete returning text + match message), ConsoleCommand/Action/Node tree, ConsoleParameterType, ConsoleContext (selection lookups), ConsoleRunner (Plan + Autocomplete + EnumerateCommands). Game command: Unciv.Core/Commands/DevConsole/RunConsoleCommand ("run-console-command"): Line + Tile/UnitId/Civ selection in the payload (the Kotlin console read them from the WorldScreen).
    Design: handlers are pure planners returning ConsolePlan(response, effect). Validate plans the line and rejects errors (invalid-target) and hints/queries (not-allowed, so they are never logged; the client shows ConsoleRunner.Plan's message); Apply re-plans and runs the effect, so replay re-parses the logged line deterministically (ConsoleLinesReplayToTheSameStateAndAreRefusedWithoutGodMode verifies via ReplayVerifier).
    Gate: GameParameters.GodMode must be set from game setup (in multiplayer: the host's lobby cheat setting; there is no command that can turn it on later), actor must be a human player (RequirePlayer, not the server). Not tied to the turn (simultaneous turns). The T192 DebugAddTechnology is a different, picker-level path and is kept; civ addtechnology is the console equivalent.
    Ported: unit (checkfilter add remove addpromotion removepromotion setmovement sethealth setxp), city (checkfilter add remove setpop setname addtile removetile religion sethealth addbuilding removebuilding setpuppet), tile (checkfilter setimprovement removeimprovement setpillaged removeroad addfeature removefeature setterrain setresource removeresource addriver removeriver setowner spawn-barbarian-encampment), civ (addstat setplayertype revealmap addpolicy removepolicy addtechnology removetechnology checkcountable), game (setdifficulty setturn add-spectator), diplomacy (all 10). Tests: CliInputConsoleTests, ConsoleCommandTests (the Kotlin DevConsoleTests.allFunctionDescriptionsMatch is EveryFormatMatchesItsPathInTheTree); GameCommandTests sample added.
    Not ported (deferred, no follow-up ticket yet): activatetrigger (civ/unit; needs UniqueValidator + UniqueTriggerActivation.triggerUnique + UniqueBuilderScreen), civ add / civ remove (scenario building, remove asks a confirm popup), game remove-spectator (save + reload + screen swap), tile find (client notification), history (UI), triggered*UniqueTemplate parameter types.
    Deviations: game setturn rejects negative values (Kotlin unchecked); ToFloat refuses NaN/Infinity (determinism); diplomacy commands refuse the same civ twice (manager lookup would fail); tile setresource draws the deposit size from tile.StateThisTile.StateBasedRandom (Kotlin used unseeded Random.Default, the engine has none); titlecaseChar is char.ToUpperInvariant; the Kotlin colors are ConsoleResponseKind (Ok/Hint/Error) for the client to colour; sub-commands sit in an ordinal SortedDictionary instead of a HashMap (output was sorted already). Responses are English only.
    Mutation on planning is forbidden: e.g. diplomacy "meet" (GetDiplomacyManagerOrMeet) happens only in the effect.
