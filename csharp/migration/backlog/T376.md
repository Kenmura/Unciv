### T376 AutoPlay: skip or shorten animations and never let them queue behind the turns
- State: In-Review [Claude-reviewer]
- Depends: none
- Source: Owner report 2026-10-30: when running AutoPlay the turns outpace the animations. Related: C047 (AutoPlay UI), T228 (AutoPlay commands)
- Fixtures: none
- Deliverables: Reproduce first (is the animation queue unbounded, or just slower than the turns?). While AutoPlay runs: skip or heavily shorten unit movement, combat, camera moves and city effects, drop any queued animation backlog when a turn ends, restore normal speed when AutoPlay stops or the player takes over; an Options setting for AutoPlay animations (skip / fast / normal, default skip); harness scenario that runs N AutoPlay turns and asserts the animation queue stays bounded and the view matches the final state; tests
- Gate: dotnet build -warnaserror && dotnet format --verify-no-changes && dotnet test
- Claimed: 2026-10-31T02:46Z
- Notes: Filed by orchestrator at the owner's request.
  - Root cause (reproduced with scenario autoplay-animations, crowd game, 80 AutoPlay turns, real frame clock): the presenter queue was unbounded and slower than the turns. Every auto-played turn queued its moves/fights (about 1 script second per turn, rising) behind the earlier ones; PresentationTimeline only speeds up by pending/6, so the backlog grew to 38.7 s (6.4x catch-up speed) and was still playing after the run ended; units were also drawn at the start of their walks while the engine was many turns ahead.
    Fix: Options setting AutoPlay animations (skip/fast/normal, default skip, stored as string "animations", sanitized). Skip: events are neither presented nor sounded during a run. Fast: 6x speed (PresentationTimeline.SpeedScale), at most 36 frames per turn, the rest dropped (CombatPresenter.Complete: end states, no sounds/particles); Complete also on stop. Normal: next turn waits until the animations end (30 s guard), then drop. Speed back to 1 on finish/stop/game switch; the backlog is cleared at run start. Bound: at most one turn of cues is ever queued; scenario asserts zero backlog when each turn's events arrive in all three modes (mutation-checked: without the wait it fails with 32 s backlog), speed 1 and empty queue afterwards, unit nodes on engine tiles, stop in fast mode, options picker stores the pick.
    Not applicable: camera moves (AutoPlay never moves the camera; Refresh keeps it) and city effects (the client has none). Not done / observed: GameScreen.Refresh() each turn (full map reload, overlays, minimap) is the remaining per-turn cost of a skip run (about 0.5-0.8 s/turn on the harness crowd game); not changed here.
    Gate: first full run had 3 network-test failures (StandbyReplication, RelayClient, HostHandoff; timeouts under load, unrelated) and one SizeRatchet failure (fixed by splitting the scenario Build); second run green.
