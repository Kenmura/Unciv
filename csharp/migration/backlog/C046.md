Deliberate deviations from Kotlin: (1) the popup is a non-modal panel under the top bar so a map click still selects the tile/unit the next line works on (hotkeys are off while it is open; Escape or the Developer Console button closes it); no on-screen history/autocomplete buttons, no unique-builder button; word-jump keys are the text field's own. (2) Enter first asks the engine to plan the line (new query console.Plan: Ok/Hint/Error + message), and only an Ok line is sent as one RunConsoleCommand (so errors/hints are never logged); Tab uses the new query console.Autocomplete (replace length, text, message, isError). Both queries refuse a game without God mode / a line over 1000 chars with the same text as the command (ConsoleRunner.GodModeRequired/LineTooLong). (3) Responses are coloured green (ran, text or "Done"), gold (usage/answer/completion list), red (refused). (4) History lines are stored trimmed, max 42, sanitized on load (ConsoleModel); history and "Keep open" persist in ClientSettings (consoleHistory, keepConsoleOpen). (5) The hotkey is a new rebindable HotkeyAction.OpenConsole, default "Quoteleft" (the Kotlin backtick); the options screen got a "Developer Console" row, so the options goldens were re-recorded (only the scrollbar/one extra row differ) and the options scenario reveals the End turn row before its second click. Godot note: LineEdit needs KeepEditingOnTextSubmit or every second Enter is swallowed, and it consumes Escape itself, so the view handles Escape.
