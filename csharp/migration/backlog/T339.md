- Notes:
  - Design update (T336, design/RELAY.md section 7 and R16): the browser talks to the read-only GET /v1/games API of the CONFIGURED relay only; it verifies every listing (cert -> fp match, signature over body, schema/text rules re-applied so a malicious relay cannot smuggle control or bidi characters), shows the short fingerprint with "first time you see this host" or "known host", greys out other proto/version, labels player counts as reported by the host, shows the relay name/contact from /v1/info. Join pins fp in the inner TLS (a first join to a stranger is TOFU-equivalent: say so in the help text, section 9). States to cover: no relay configured (link to setting), relay offline, relay too old, empty list, error. The host checkbox "List this game publicly" is off by default, disabled with an explanation for token-only games, per game. Uses the T338 listing publisher; no free-text description exists. Acceptance: RELAY.md R7 (client verifier), R10, R16.
  - CORRECTION (review round 2) to the design note above; RELAY.md wins: the browser reads the directory over the tunnel op get (sections 3, 7, 8) of the CONFIGURED relay, with a 512 KiB / 10 s cap on the reply; the optional HTTP listener is never needed by the client. Owns R10 (UI) and R16.
  - Deviation (deliberate): the list shows the relay's round trip ('ping N ms' in the header), not a ping per game: a per-game ping would mean connecting to every host, which the directory design forbids (a listing never carries an address). Player counts are labelled 'as reported by the host'.
  - Deviation: only the protocol/version mismatch greys a row (plus missing base ruleset and a full game). A differing mod set or ruleset hash stays joinable with a note, because JoinScreen offers the mod sync (T247) first. Join hands off to the existing JoinScreen (Begin(invite, password)) so the trust prompt, key-changed stop and refusal texts are reused; the invite carries the listed fp, so the inner TLS is pinned to it. A first join to a stranger is TOFU-equivalent and the dialog says so.
  - Implementation: Core ListingRules/ListingVerifier are shared by the relay and the client (relay ListingValidator now delegates, one rule set); RelayDirectoryClient.FetchAsync uses two tunnel gets (/v1/info for name/contact/listing policy/ping, then /v1/games) with the 512 KiB / 10 s cap (RelayChannel.ReadLargeAsync), re-verifies each entry and re-applies the query client-side so a relay cannot widen it. Refresh therefore opens two connections. The Browse button sits on JoinScreen (main menu untouched, so its goldens did not change). HostScreen: 'List this game publicly' (off by default, disabled with a reason without a relay; no token-only games exist yet, so that explanation is not needed) plus a live toggle while hosting.
