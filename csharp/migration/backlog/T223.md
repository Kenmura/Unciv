Added: Query{queryId,queryType,payload} / QueryResult{queryId,ok,code,payload} (Net/Messages.cs; the type key is queryType because `type` is the frame discriminator, as for Command); Net/Remote/RemoteQueryPolicy.cs (per-query allow/deny + reason + rate cost for all 37 registered queries, undecided = denied; RemoteQueryPolicyTests enumerates the real registry so a new query without a decision fails, and stale entries fail too); Net/Remote/RemoteQueryHost.cs (host dispatch, see below); Net/Remote/RemoteQueryClient.cs (async QueryAsync<T>, queryId correlation, pending cap, cancellation, FailAll on disconnect). design/SERVER.md 6.1 updated.
    Design: GameHost (T178) and ClientSession (T180) do not exist yet, so the dispatch is a plain class both will call: T178 calls `RemoteQueryHost.Handle(sessionId, boundCivName, query, QueryContext(game), viewSeq, resolving, nowMs)` on the game actor (it owns no thread or clock) and `EndSession` on disconnect; T180 owns a `RemoteQueryClient`, passes its send delegate and feeds every incoming QueryResult to `Complete`, and calls `FailAll` on disconnect. Order of checks: per-session token bucket (every message costs 1) -> `turn-resolving` while Resolving -> exposure policy (denied == unknown-query, byte-identical to a type that does not exist) -> cache per (viewer, type, payload) for one viewSeq -> cost-based rate limit (extra cost of heavy queries; cache hit costs only the 1) -> run. Heavy (5 tokens): units.ReachableTiles, PathPreview, AttackableTargets; bucket 40 tokens, 20/s per session (RemoteQueryLimits). A result over MaxFrameBytes-1KiB is `result-too-large`.
    Existence-oracle collapse (deliberate deviation from the local QueryResponse): on the wire every failure the query itself raises (QueryException of any code, unknown viewer) becomes the single code `query-rejected` with no text; only unknown-query, malformed-query, rate-limited, turn-resolving, result-too-large, internal-error exist. Local (in-process) callers still get the rich QueryResponse.
    Audit result: DENIED remotely: victory.Progress (iterates game.Civilizations, lists every major civ's milestone progress and civ counts), empire.TradeHint (probes AI valuation on raw civs), console.Plan and console.Autocomplete (whole-GameInfo cheat console). Follow-up T240 rewrites them. ALLOWED with a recorded reason: everything else; EmpireQueryHelpers.KnownCiv answers an unmet civ like a missing one (and the collapse hides even that); empire.DiplomaticVoteResult, CityStateQuests, SpyDestinations and the victory.Rankings/Scores/Demographics/History pages read raw civs but drop or anonymise civs the viewer has not met and honour HideOtherCivilizationStats (as Kotlin shows the numbers of anonymous civs, a deliberate residual: an unmet civ's score row is visible when the game setting allows it). Not audited line-by-line in this ticket: the View-based queries (units.*, cities.*, tiles.*, empire.* panels) are allowed on the strength of the T185 contract (Run only sees GameView); a reviewer who finds one that reaches around the view should flip its entry to Deny.
    Caching assumption: results are valid per viewSeq; T178 must bump viewSeq on every logged command including server commands (ProcessEndTurn etc.), and must pass resolving=true for the whole Resolving phase.
    Mutation survey of the new tests: 26 mutants of RemoteQueryHost/RemoteQueryClient (resolving, policy, cost, cache seq/key/bound/id, clock Max, refill cap, error mapping, size cap, pending cap, cancellation, send-failure cleanup): all killed after adding the backwards-clock recovery assertion (the first survivor); mutants that stop completing a cancelled query are killed by a hang.
