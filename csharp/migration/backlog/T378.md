- Notes:
  - Implemented (client-side, as the ticket says). Design: TileOwnerMemoryStore (Unciv.Assets) keeps one small JSON file per game key and viewer under <profile>/owner-memory/ (name = hash of key+viewer, so ids can never act as paths). GameScreen restores it in Start/BindOwnerMemory and saves whenever TileOwnerMemory.Remember reports a change (only owners of tiles IN SIGHT are ever remembered; the host protocol is unchanged, fogged owners are still withheld, tested against the real SnapshotBuilder). Key: LocalHost = game id; joined net game = "host:"+host key fingerprint (new ClientSession.HostFingerprint), because the game id is deliberately withheld from clients. Guards: (1) the file records the turn its contents last changed; a game at an EARLIER turn (older save loaded) ignores it so borders from the future never show; (2) a terrain signature over the remembered tiles must match the current snapshot (tile present, same BaseTerrain), so a NEW game under the same host key and civ cannot inherit it; (3) damaged/oversized(16 MB)/unknown-version file = no memory, replaced on next save; failed write = memory stays in RAM. Deliberate limits: a host takeover (new host key) starts with empty memory (the open ends fade as before); memory files of abandoned games are never deleted (a few hundred KB each at most) - not worth code now, noted here. Tests: TileOwnerMemoryStoreTests (round trip equality, fogged borders identical after load, per game/viewer, nasty ids, future turn, other map, damage), NetVisibilityTests (stored owners only for tiles in sight, file leaks no hidden civ/seed/game id), NetGameSessionTests reconnect+restart test, BordersScenario harness assertion (llvmpipe run passes, goldens unchanged).
