On a checkpoint mismatch or a command that no longer validates: FELL BACK to that last good snapshot, the log after it is set aside in corrupt/diverged-after-<seq>.log, game continues (RecoveryOutcome.FellBackToSnapshot, DivergedAtSeq in the report for the host to tell the lobby; clients ahead of it get a Snapshot from Resume). Tests via the internal WrapLog seam (flaky stream).
          - (Auditor/security) game.json and the log header hold the T230 host secret but were created with the umask (0644). Every store file is now 0600 and every store directory 0700 (UnixCreateMode; Windows unchanged). history/ copies and corrupt/ files too. Exports must still use CommandLogHeader.WithoutSecret().
          - (Adversary) Snapshots rejected by recovery (ahead of the log, disagreeing with its checkpoint) stayed in the directory: once the log grew past their seq they looked like snapshots of the new history, and they crowded the good ones out of the newest-N retention. Open now moves them to corrupt/rejected-snapshot-<seq>.json.gz.
          - (Adversary) TrySnapshot at a seq where the log already has a checkpoint with a different hash (the game changed without a logged command) wrote a poisoned snapshot recovery would reject, so the game could not come back. AppendCheckpoint now throws GameStoreException when the seq already has a different hash; snapshots go through it.
