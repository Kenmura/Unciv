      - Recovery (review point 3 resolved): torn/unparsable/out-of-order tail cut off (kept in corrupt/tail-after-<seq>.log) and reported; newest snapshot that loads and agrees with the log checkpoint at its seq + VerifyTail. A snapshot that is unreadable is moved to corrupt/ and an older one tried. On a checkpoint mismatch or a command that no longer validates: FELL BACK to that last good snapshot, the log after it is set aside in corrupt/diverged-after-<seq>.log, game continues (RecoveryOutcome.FellBackToSnapshot, DivergedAtSeq in the report for the host to tell the lobby; clients ahead of it get a Snapshot from Resume). No snapshot usable: replay from the header (unrotated logs only), else GameStoreException. Deliberate simplification: the fallback drops back to the snapshot, not to the last verified checkpoint.
      - Snapshots (review point 1): TrySnapshot refuses while TurnState.Phase == Resolving (T200 finding 4); the host retries at the next safe point. CloseCleanly snapshots when safe and always writes the clean marker (seq); a resolving shutdown relies on snapshot + log tail. A snapshot also appends the log checkpoint for its seq so recovery can verify the snapshot itself. Mid-Resolving snapshots are NOT proven (not attempted).

Rejected commands are not logged (a retry re-validates, deterministic). Wiring this into the host's message handler is T-host work (nothing in Net calls it yet).
