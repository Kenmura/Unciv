- Notes: Phase 5. Two bugs. (1) Where two civs' territories share an edge, both borders are drawn on top of each other (one hides the other); each civ's ribbon must be offset inward onto its own side of the edge so both colours show side by side. (2) At the edge of vision, border edges are falsely drawn along the boundary between a visible tile and an explored-but-fogged tile, as if the territory ended there, although the city (e.g. Osaka) clearly continues into the fogged region. Borders must be computed from the real owner of every explored tile, including fogged tiles the player explored before (use the last-known owner for fogged tiles), and drawn only where the owner really changes, never where visibility changes. Unexplored tiles must not show borders. Add unit tests for BorderEdges over a visible/fogged/unexplored mix and a shared-edge case; add or update a scenario screenshot.
  - Implemented. (1) EdgeEnds takes an inset (hexagon shrunk about its centre so corners stay shared); the overlay insets each ribbon by half its width so two civs' ribbons on a shared edge sit side by side. (2) BorderEdges now takes a TileOwnerMemory: fogged tiles use the owner last seen while visible (client-side, filled in GameScreen.Refresh before Rebuild, cleared on Start with another session so hotseat/load never leak owners); a fogged tile with no memory is unknown and draws no edge against it, so borders appear only where ownership changes, never where visibility does. Snapshot is unchanged (Owner still only on visible tiles), so the fog anti-leak guarantee and view hashes are untouched. Deliberate limitation: memory is client-only and empty after reconnect/load; the outline is open there until tiles are seen again; follow-up T303 (server-side per-civ memory). Tests: MapOverlaysTests (visible/fogged/unexplored mix, shared edge inset, memory, clear). Scenario: new "borders" (goldens borders/*, screenshots.json T298); flat-city goldens road/improvement/city re-recorded (border now inset). Review: isolated adversarial x2; the blocking finding (memory never cleared on session switch) fixed and re-reviewed with no findings.
